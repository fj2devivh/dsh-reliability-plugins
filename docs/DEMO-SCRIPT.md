# 3分钟录屏脚本（DEMO-SCRIPT）

> 目的：GitHub README 的演示视频 + 面试时备用。中文口播，英文字幕。
> 录制工具：OBS。录完剪成 2:40–3:10，配英文字幕，放 README 顶部。
> 核心原则：**每一分钟都在展示"判断与验证"，不展示"代码量"。**

---

## 0:00–0:20 ｜ 钩子：问题（不要寒暄）

**画面**：打开一个被上下文污染的会话截图（或现场演）：意图层读了大量源码日志后，输出偏离了最初的目标——划红框标出偏离处。

**口播**：
> "用大模型 Agent 驱动真实项目，我最常遇到三种事故：它读太多、忘了我要什么；它说做完了、其实没有；它的脏数据往上层传。我的解法不是更好的提示词，而是在工具层让它'做不到'。这是我在 DeepSeek 官方 Harness 上搭的 10 插件可靠性体系。"

## 0:20–0:50 ｜ 证据一：能力级隔离（4 vs 11）

**画面**：运行 `dsh-executor-gate\_verify-tool-register.mjs` 第 4 节，真 ToolRuntime 打印两个工具表。

**口播**：
> "意图层的工具表里，读文件、glob、grep、shell 根本不存在——不是被拦，是没有。它只剩四个工具：派子代理、派审计、和两个只读指南针。指南针的白名单只有人的原话和验收报告。实测：意图层可见 4 个工具，执行层 11 个。"

**画面**：放大输出对比（4 vs 11）。

## 0:50–1:40 ｜ 证据二：执行层预算租约（默认冻结 + 预算耗尽自动停）

**画面**：打开一个 dual 会话，任务书里带【授权】段（工具预算：write 5 次、范围 /output/xxx）。发任务，观察执行层工作。

**口播**：
> "执行层出生即冻结——这是 9 月 15 日事故后立的规矩：原来只有意图层被管，执行层继承全套权限，想改什么改什么。现在权限按任务租：工具乘范围乘次数。烧完额度它会自动停下，报告'预算耗尽、任务未完成'——这是正确行为，不是偷懒。"

**画面**：演示一次预算耗尽的停止（或 smoke 测试中的对应断言变红变绿的回放）。

## 1:40–2:20 ｜ 证据三：负对照（这套体系最值钱的一分钟）

**画面**：跑 `preflight-dsh.mjs`，全绿。然后展示 smoke 测试里"少一个眼睛的掩码必须变红"的负对照用例：故意制造一个坏 Config，看判据变红。

**口播**：
> "我所有验证工具都内建负对照：每个检查都带一个'必须变红'的反例。反例不变红，整份结论不可信。改完插件最怕重启进恢复模式——preflight 在重启前预测'还打不打得开'。9 月份它抓到过三次真问题。"

## 2:20–3:00 ｜ 收尾：市场对照 + 定位

**画面**：打开《市场对照分析》文档的 601 插件统计；切到 README 的架构图。

**口播**：
> "我把官方生态 601 个插件抓下来做了机制级对照。比如市场上有插件解决'这一轮话没说完就停了'，我解决的是'会话断了、进程重启了，目标还在不在'——层次不同，两个可以同时装。分析里我撤回过两条自己的建议，因为它们用错了口径。这套东西解决的是 context engineering 里最硬的那部分：不靠模型自觉，靠工程兜底。"

**结束帧**：README 仓库地址 + 邮箱。
