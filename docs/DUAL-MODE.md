# 双区模式（意图层 / 执行层）

你要的三件事，逐条对应到实现：

| 你的要求 | 实现 | 强度 |
|---|---|---|
| 一个分区专门理解意图 | `dual` preset：persona 是「意图层」身份，只做理解/拆解/定验收/验收 | 提示词（每轮注入） |
| **可以读取和运行，但不能修改** | `dsh-intent-guard` 插件用 `ctx.tools.restrict({ deny: ['write','edit'] })` **剥夺工具 schema** | **硬约束（工具层）** |
| 一个分区专门执行 | 意图层用 `subagent` 派出的**可继续子会话**（执行层），有自己的上下文 | 原生机制 |
| **不是我一说话就开始执行** | 意图层必须先把规格（目标/范围/验收标准/证据要求）定清楚才派活 | 提示词 |
| **执行层不许乱来** | `dsh-executor-gate` 插件：**默认冻结** + 意图层按任务发「工具预算」 | **硬约束（工具层）** |
| 可选的开关 | 会话级：开新会话选 preset。要单 agent 就选回 `standard` | 原生机制 |

> 2026-09-15 补上的那一格：**原先只有意图层被约束，执行层完全没有约束** ——
> 它一被创建就继承 `standard` 的全套能力，可以随手改任何文件、搭任何机制、跑任意多轮实验。
> 这正是「意图层很听话、执行层蠢」的机制性根因。见下面第五节。

## 装了什么

```
C:\Users\<you>\.dsh\.agent-presets\
  dual\             双区（意图层；执行层由它派出）

D:\<dsh-plugin-root>\插件\
  dsh-intent-guard\   意图层的工具掩码（被 dual 引用）
  dsh-executor-gate\  执行层的权限管理条例（被 dual 引用）
  dsh-criteria-gate\  判据登记闸（内容级 + 规矩级；被 dual 引用）
  dsh-endstate-loop\  终局闭环（方向级：缺口器 + 累积台账；被 dual 引用）
  dsh-endstate-view\  右栏「终局」面板（客户端插件；挂在 profile desktop+web 上）
                     打字修改走 /endstate 命令 → **调用意图层的真工具**（规则零复制，
                     会话日志留 command/run+done，**不叫醒模型**）
  build-presets.mjs   从 standard 组合重新生成 dual（幂等）
```

`dual` 是**从随产品交付的 `standard` 组合复制后精准改写**的 —— 不是从零写。
只动了两处：persona（换成意图层身份）+ 追加本层独有的插件行。其余能力一字不改
（`verify-presets.mjs` 逐行核对这一点）。

**一个 preset，不是两个。** 曾经是「意图层 / 执行层」两个并列条目 ——
那等于把内部分工暴露成两个要用户自己选的东西，已废弃（`build-presets.mjs` 会删掉旧目录）。

## 怎么用（开关）

**preset 只能在「还没有产生历史」的会话里切换。** 所以：

- **双区模式**：新建会话 → 选 `dual` → 在这里跟意图层说话。
- **单 agent 模式**：新建会话 → 保持 `standard`。

想改默认值，就改 `$DSH_HOME/settings.yaml` 的 `agent-presets.default`。

## ⚠️ 「不能修改」的真实边界（必须说清楚，不吹）

工具掩码剥夺的是 **`write` / `edit` 的 schema** —— 意图层**连「能改」这个选项都看不见**。
这是硬约束，不是请求。

但它**不是文件系统级的安全边界**：意图层仍有 `subagent`（它可以派人去干活）。
要真正的只读，得在环境层做（只读挂载 / 沙箱 write 目录），那不在本插件范围内。

> **2026-09-19：多了一道「不能看」的闸门，而且是能力级的。**
> 用户的原话：「是需要**能力级的不可看**，只有那些最重要的东西作为意图层的指南针，
> 因为意图层就**必须贯彻我的意志，不能自作主张**。」
> 落法：`read` / `read_image` / `glob` / `grep` / `pwsh` / `bash` 被**从意图层的工具表里整个拿掉**
> （真 `ToolRuntime` 上验过：它只剩 `subagent` / `dispatch_audit` / `read_compass` / `list_compass`，
> 而执行层照旧全套）。它能自己打开的只有**指南针**：人的原话与判据（`notes` 里的 `.md`、
> `notes/_user_requirements.json`）、终局定义与任务与台账与《鉴证报告》（`notes/_endstate/**`）。
> 想放宽只能**人**去改 `cleanRoom.allow`。详见 `dsh-intent-guard\README.md` 第二节。

`dsh-intent-guard` 的 deny 表**只放已核实存在的全局工具名**，因为 `tools.restrict()`
对未知名字是**响亮失败**的 —— 写错一个名字会让意图层整个起不来。所以：
`str_replace_editor`（本机组合里没有）和 `run_code`（`restrict` 明确拒绝）都**没有**写进去。

## 五、执行层的权限管理条例（2026-09-15 新增）

**根因**：双区原来只锁了意图层。执行层拿到的是「standard 全套能力」——
没有范围、没有额度、没有审批。它「蠢」不是模型问题，是**没人给它立规矩**。

`dsh-executor-gate` 把执行层从「默认全权」改成「**默认冻结、按任务发预算**」：

| 条例 | 实现 |
|---|---|
| ① 默认冻结（白纸开局） | 执行层一被创建就套 `ctx.tools.guard()`；没有租约时**一个文件都写不了** |
| ② 权限审批流 | 执行层 `request_permission` 申请 → 意图层 `grant_permission` 批准；或派活时直接写授权包 |
| ③ 范围锁 + 时间锁 | 授权包按工具给 `范围`（目录前缀 / glob）与 `额度`（次数）；到点自动冻结 |
| ④ 定律 vs 工具的边界 | 闸门自身的源码**任何租约都不可授权**；执行层不能给自己授权；挑战约束三次即熔断 |

授权包就写在任务书里（一段以 `【授权】` 开头、含 `工具预算:` 的文字）：

```yaml
【授权】
任务ID: "TASK-001"
工具预算:
  read_file:  { 额度: 无限, 范围: "/data/**" }
  write_file: { 额度: 5次,  范围: "/output/schedule_*.json" }
  run_test:   { 额度: 3次 }
预算外行为: "禁止。如需超出预算，必须向意图层申请。"
```

**预算 = 工具 × 范围 × 次数**，不是一个全局桶。**预算里没列出的工具 = 禁止使用。**
额度烧满时执行层**自动停下**并报「预算耗尽，任务未完成」—— 那是正确行为，不是偷懒。

完整说明（含全部字段、边界、与产品约定的关系）见 `dsh-executor-gate\README.md`。

## 六、规矩的来源闸：不许在任务书里发明规则（2026-09-19 新增）

上面那四条管住了**执行层**。但它们全都默认**任务书本身是真的** ——
于是留下一个缺口，而且这个缺口一路绿灯：

```
意图层在任务书里自己写一条规矩（真源文件里没有，甚至正好相反）
  ⇒ 执行层照着做
  ⇒ AST 比对干净（符号都在白名单里）      ← dsh-criteria-gate 闸 2 通过
  ⇒ 判据位点也挂得上                     ← 闸 2 通过
  ⇒ 验收核「新符号 ⊆ 白名单、位点 ⊆ CRIT」← 闸 3 通过
  ⇒ 落树的东西已经不是你要的了
```

`dsh-criteria-gate` 补了两道**规矩级**的闸。它们的对象不是执行层，是**意图层写出来的任务书**：

| 闸 | 规矩 |
|---|---|
| **① 挂源闸** | 任务书里每条**规范句**（含 `必须/应当/不得/一律/默认/取序/判定/强行`，或 `→` `⇒` 箭头）**必须挂出处**，只有三类合法：`用户原话: <逐字>`（逐字命中裁决节）／`判据: CRIT-xxxx`（已登记且文字逐字一致）／`<文件路径>:<起>-<止>`（**插件打开那个文件核**） |
| **② 空缺闸** | 原文件没说的地方**不许自己定值**。唯一合法写法：「此处原文件未规定 ⇒ 执行层停手并向意图层回问」（这一条**免出处**，但会被单独报出来供审计） |

**引用核不到就等于没有出处**（文件被移走、行号越界、区间里核不到 —— 都按没出处办，
并把区间实际内容打出来）。合法的拒绝理由是 `意图层自己标了「出处：无」⇒ 那不算出处`。

### 第 ③ 类出处（`路径:起-止`）的核法分两级 —— 强度差很远

**有坐标 ⇒ 硬核（次序比对）。** 坐标是机器可比的：

```
句中   (4,1) → (4,0) → (3,0) → (3,1)    区间里相同次序     ⇒ 放行
句中   (3,1) → (3,0) → (4,0) → (4,1)    反序，不在区间次序里 ⇒ 拦下
```

**顺序、起点、方向都是规矩的一部分**；标点措辞可以改写，**坐标改不得**。
这一条压在你的实际内容上正合适 —— 取序全是坐标。

**没有坐标 ⇒ 只能软匹配**（"句中最长的三个片段之一在区间里出现"）。
这条很弱：一个 `N4W` 命中就能让一整句自造规矩过关。所以输出里现在**如实写明核到了什么**：

```
依据：坐标链已按次序核对（(4,1) → (4,0) → (3,0) → (3,1)）     ← 硬
依据：只核到片段：N4W（仅证明提到过，未证明句意）                ← 软，别当核实
```

### 一句话两个主张、只挂一处出处 ⇒ 拦

```
农忙时先扫水全模块 → 再扫收全模块，然后把 N4W 和 N4E 合并成 8 格。出处：手工排班\模块术语表.md:459-466
                                  ↑ 真（第 465 行确实这么写）    ↑ 编的，共用同一处出处 ⇒ 拦
```

出处证不了"你新接上去的那半句" —— 而这正是自造规则最省事的伪装。**一个主张一处出处。**

> **这两道闸拦不住什么，写在明处**：一个**单独成句**、不带坐标、又不带连接词的自造主张，
> 只要蹭到一个片段，现在仍然过得去 —— "忠实改写"和"蹭个词再说别的"在这类句子上
> 共享的信息太少，机械判据分不开。**别把"闸 4 通过"当成"任务书已被审核过"。**
> 要硬结论就给坐标，或把出处写成更精确的区间。

### ⚠️ 出处不外借 —— 这条改了两轮，前后都漏过真事故

任务书最常见的排版就是「**规矩一句，出处紧随其后**」：

```
不强行套 8 格蛇形 ⇒ 让两个工人各走自己模块的 4 格序。      ← 自造规则
N4W 农忙时从 (4,1) 起走 (4,1) → (4,0) → (3,0) → (3,1)。出处：手工排班\模块术语表.md:459-466
```

- 第一版往前看两行、只要那行不含规范关键词就借它的出处 ⇒ **第一行借到了第二行的出处**。
- 第二版改成"下一行短、且带标记就能借" ⇒ **还是漏**：第二行自己就是规范句，可它带着标记。
  更要命的是 —— **只要第二行的出处是真的，第一行那条自造规则就会真的过闸**。

现在的硬要求：**能借的那一行必须是"纯出处行"** —— 摘掉标记之后不剩任何实质内容
（只剩标签、列表编号、括号、标点）。「自带出处的规范句」永远是它自己的句子，**不外借**。

### 派活时怎么用

`declare_whitelist` 多了一个 `taskbook`（或 `taskbook_path`）参数：

- **带了任务书** ⇒ 先过闸 ① ②；不合格 ⇒ **拒发白名单，且白名单文件不落盘**
  （位置在写白名单之前 —— 授权一旦落盘执行层就已经在动工，事后追认拦不住任何东西）；
  合格 ⇒ 结论**跟着授权一起回去**，意图层才知道自己哪几句被判成了规范句、出处核没核到。
- **没带任务书** ⇒ 闸看不见，默认只留一条 `GATE-TB OBSERVE` 告警照发（历史欠账；
  收紧开关是 `requireTaskbookOnLease`）。
- 另有 `check_taskbook` 工具，**意图层与执行层都能调**（只读）：派活前先自审一遍，
  或者执行层核自己收到的任务书。输出逐句列「规范句 / 放行（附出处）/ 拦下（附行号 + 原因）」。

> **它不判断"这条出处对不对"，只判断"这个出处核不核得到"。**
> 核到的是"真源文件第 459–466 行确实写着这句话"，不是"这句话本身是对的"。
> 要求插件判断对错，就是把意图层的职责搬进插件 —— **那是扩权**。
> 完整说明见 `dsh-criteria-gate\README.md` 第三节。

## 六之二、知识准入闸：把「知道」变成权限（2026-09-19 新增）

用户的原话：

> 「一句话：**把「知道」变成权限，而不是自觉**。插件现在的判据是「你能不能做」。
>  要改成「**你知道不知道**」也参与判据。」
> 「为什么必须是「拒绝操作」而不是「提醒」—— 这一轮已经证明：提醒我可以不理……
>  只有让不懂的人做不了事，这条才不会复发。」
> 「我这一轮花了很久才发现「**盘上有 ≠ 我知道**」—— 因为插件从没告诉过我，
>  我的世界里哪些是自动到场的。」

| 件 | 是什么 |
|---|---|
| **准入** | `knowledge_required` 里每条 = `id / source / marker / required_for`。没确认过 ⇒ **拒** `write_file`（write/edit/变更类 shell）、`run_test`（pytest / node --test…）、`subagent`、`dispatch_audit`、`plan_task` —— **只读一律放行**（用户明说：别把闸设在"读"上，否则会话开头就卡死） |
| **确认要证据** | `confirm_knowledge({id, quote})`：`quote` 必须是那一段里**逐字出现**的一句话。理由是本项目的老规矩：**"我确认了"不算证据** |
| **可查** | `knowledge_status`：**你的世界里每回合自动到场的东西**（路径 / 字节 / 指纹）、通道预算、你还缺哪一段、现在哪些操作被挡 —— 并且把 *开场就在* / *已进场* / ***还没进场*** 三种状态分开说 |
| **过期** | 通道内容一变（或那一段本身变了）⇒ 确认作废、操作重新被挡。理由：**拿着旧规则干活比不知道更危险** |
| **容量** | 通道渲染字节接近 `maxBytes`（默认 85%）⇒ 日志 + 状态 + 每回合提示三处报警。超了产品会**先丢宽泛的文件、再截断最具体的那个**，模型看到的是残缺规则 |
| **留痕** | `notes/_endstate/knowledge.jsonl`：哪个会话、什么时刻、凭哪份来源（段指纹 + 通道指纹 + 引用的那句原话）通过 / 失效 |

⚠️ **配置坏了（源文件或标记找不到）只报警、不拦**：人还没写那段规则时拦下来，
等于让整个双区写不了任何东西 —— 把配置问题变成死锁是更坏的结果。
详见 `dsh-knowledge-gate\README.md`。

## 六之三、两处「确认在骗人」的修法（同一天的两条缺陷）

用户报的两个症状属于同一类：**回执说的是"我做了什么"，不是"现在是什么"**。

| 症状（用户原话） | 修法 |
|---|---|
| 「grant_permission 回「已授权」、打印预算、打印写范围 —— 而实际生效的是 read_file 1/1、写范围空。**六个执行层被拒写**。」 | **回读核对**：判据与执行层的守卫**同源**（`leaseFor`），逐项比「你要的」与「实际生效的」（写范围 / 每个工具的额度 / 禁止碰 / 任务 id / 时间锁）。**不一致就不打印成功框**，改成 `❌ 授权没有生效` + 实际生效值 + 对不上的地方 + 下一步（查台账 / 重发 / 写进任务书）。核对结果也记进审计（`grant_verify`） |
| 「给已经收工的执行层发消息 ⇒ 回「已送达」，实际没人会读。」 | **发消息前查活**：`send_message` 过一道守卫，按产品的真实语义给**三态** —— 活着 ⇒ **排队中**；不在活着但**可继续** ⇒ **排队中（会冷启动一轮）**；**一次性**（one-shot，叫不醒） ⇒ **建议新建会话**；名册里没有 ⇒ **已拒绝（原因）**。拒绝话术里写明「"已送达"只对活着的目标成立」。`lease_status` 里还加了一份**发消息可达性**名册，发之前就能查 |

> ⚠️ 为什么"发消息前查活"要用**轮询缓存**：产品的名册（`subagents.listChildren`）是**异步**接口，
> 而 `tools.guard` 是**同步**判据（返回 Promise 会被当成"拒绝"）。所以名册由定时器刷进缓存、
> guard 只读缓存 —— 而"它现在活着吗"那一条始终是实时判的。

## 七、终局闭环：让"下一步做什么"被算出来（2026-09-19 新增）

上面五节都是"这一步有没有违规"。**没有一件回答"这一步该不该做"** ——
而后者才是**局部最优**的来源，而且它不是贪心，是**信息结构**的产物：

> 每个决策节点上只有"当前这一步"的信息（上一个报的红、眼下的分数），
> 没有"整座大厦"的信息 ⇒ 只能选对当下最优的那一步。
> 任务从"上一个错"来，不从"终局还缺什么"来 ⇒ 每一轮都在让当前这个错消失 ⇒ **打补丁**。

⇒ 解不是"更好地选"，是**让"下一步做什么"被算出来**：

```
可执行终局定义  →  自动缺口器  →  任务队列  →  派活  →  实测重算缺口  →  回到第一步
```

`dsh-endstate-loop` 就是这条闭环。四件东西，各消灭一个判断：

| # | 东西 | 它消灭的判断 |
|---|---|---|
| 一 | **可执行的终局定义**（每条 = 一个能跑的探针 + 可核出处） | "这算不算朝目标走" |
| 二 | **自动缺口器**（要求 X、实测 Y ⇒ 缺口 = X−Y） | "现在缺什么" |
| 三 | **算出来的任务队列**（四条规则：依赖深度 → 探针坏掉优先 → 声明 order → 声明序，**没有第五条**） | "先做哪个" |
| 四 | **只增不减的台账**（哈希链 + 累积节点） | "回退 / 覆盖 / 抹平" |

**检验标准写在插件的输出里**：「下一步做什么」如果还需要任何一次判断/选择，缺陷就还在。
每一处仍不得不问人的地方都登记成 `judgment_needed` 并**计数** —— 目标数字是 **0**。

### 为什么是向量，不是分数

分数是标量代理，只有一个方向，天然诱导局部最优；而且**它是唯一会自动产生的东西**，
所以它会成为事实上的目标函数。缺口向量里的每一条都带着自己的
**当前值 / 目标值 / 差值 / 出处** —— 没有一个数字能支配全局。

### ⚠️ 它自己会长出的那个局部最优：**把尺子改松**

"绿"有两种方式：**让系统更好**，或者**让尺子更松**。终局一旦是可执行判据，
"改判据"就会取代"改代码"成为新的补丁形式 —— 这个插件自己就是最容易被这么搞的东西。

所以改探针必须给理由，而且改动时会**同时跑旧探针和新探针**：
「旧判未达成、新判达成」⇒ 记 `loosened` 并单独计数，判定升到 `gaming`
（**严重度高于打补丁** —— 打补丁至少还在动系统）。

### 三态：**测不出来 ≠ 达成**

`达成 / 未达成 / 测不出来`三态分开报。只剩"测不出来"时 ⇒ 阻塞在**修探针**，**不报完成**。
同理：所有条款都达成、但有条款**没有可核出处** ⇒ **也不报完成** ——
终局定义本身也是判据，判据没有出处，那个"完成"就是自造的。

### 验收 = 这一步给全局增加了什么（不是"这一步对不对"）

`record_node` 的 `delta` 必填，**失败同样必填**：分数掉了是一条新信息、改了没效果也是一条。
真的什么都没测出来 ⇒ 写"无"，但必须同时填 `unknown`（说清现在什么变得不确定了）。

**回退**：内容可以回到旧版本，但"为什么回去"必须登记成节点 ——
**丢掉的从来不是内容，是那份为什么**。执行层写文件/跑 shell 前的守卫会拦回退，登记后放行。

完整说明（十一个工具、五种探针、五个机械指标、退场进历史、任务层、空气、鉴证报告、诚实边界）见 `dsh-endstate-loop\README.md`。

### 审计层：**意图层只准看报表**（2026-09-19 新增）

用户的原话：

> 「'意图层本来也需要重新跑一遍执行层的代码，用来检测执行层有没有搞出来问题'
> —— **这就是它越界了，也是它被污染、变蠢、最后搞发明的根本原因。**」
> 「**把它的眼睛蒙上，只允许它看报表。把它的手绑住，只允许它写任务。**」
> 「**严禁意图层读取原始代码、原始报错日志。意图层只能接收由审计层生成的《结构化验收报告》。**」

于是双区里多了一条四层流水线：

```
人        → 意图层        → 执行层        → 审计层            → 意图层
写终局      分解成任务      只看到任务书     黑盒跑验收           只读《鉴证报告》
（物理）    （下发标准）    （不许改终局）   （不能写、必须带负对照） （算缺口、派下一步）
```

| 落点 | 是什么 |
|---|---|
| **视界** | `intent-guard`：**能力级拿掉** `read`/`read_image`/`glob`/`grep`/`pwsh`/`bash`，只留指南针 `read_compass` / `list_compass`（实现里只有一条白名单：原话 / 判据 / `notes/_endstate/**`）；第二层 guard 再按路径兜底 |
| **审计员** | 预设里的第二个 `dsh-tool-subagent` 挂载：工具名 **`dispatch_audit`**，自带人格（只跑不读源码 / 不能改 / 必须带负对照 / 证据是命令+输出）与工具掩码（`deny: write, edit`） |
| **报告** | `file_audit_report` 收下 → `notes/_endstate/audits/<clause>-<时间>.json` + 台账 `audit` 节点。它**不判对错**，只打回三种：没证据 / 没负对照 / **负对照也绿了** |
| **空气** | 每个回合的空气块里只列《鉴证报告》：每条条款的最近判定与缺口；没验过的条款单独点名"还没有审计"；坏掉的文件说"是坏了，不是没有" |
| **面板** | 条款卡片里一行 `鉴证：符合/不符合/测不出来`，外加一整栏「鉴证报告（审计层交回来的现场）」——**人看得到全部**（证据 + 负对照可展开） |

#### ⚠️ 审计层也要授权（和派活同一个机制）

审计层**也是执行层**（`origin === 'subagent'`），所以它照样吃第五节的默认冻结：
**没有授权时改不了任何东西、也跑不了 `pytest` 这类测试框架**。
它能跑的是**只读类**命令 —— 例如 `python scripts/v6_prefix_check.py --upto-day 12`
（不带重定向的），这一档在冻结状态下**本来就放行**，因为「熔断后仍要能读、能跑只读命令」
是刻意留的（否则它连"把情况说清楚"都做不到）。

所以当这次验收**非要用到被拒的能力**（跑测试框架 / 写临时夹具）时，
授权包要写进**派审计的那段说明**里，格式与派活一模一样：

```
【授权】
任务ID: "AUDIT-T-001"
工具预算:
  run_test:
    额度: 3次
预算外行为: "禁止。超出预算就判测不出来，并在报告里写清缺什么。"
```

⚠️ **不给它写权限去改被审计的产物**（那等于让审计员改卷子）；真要写夹具，只给一个临时目录的范围。
审计层的人格与工具掩码已经把 `write` / `edit` 拿掉了，所以它**结构上**改不了被审计的东西。

## 可视化分区（2026-09-15 已做）

**一个分区专门执行，另一个分区专门看它。** 右栏现在有一个常驻的 **执行层** tab：
列出本会话的执行层（可继续 subagent）子会话 —— 运行状态、token 累计、活跃轮次耗时 ——
点一行就打开它的 transcript。

> **只显示 24 小时以内的。** 执行层会越攒越多，全列出来就得靠滚轮翻半天才能找到最新那条。
> 所以超窗的自动收进每棵树的 **`▸ 24 小时以外（N 个）`** 分组行，**默认折叠**，点一下展开。
> 判"多久没动"用 `updatedAt` 与 `subagentTiming.active.through` **里更晚的那个**；
> **两个都没有 = 时间未知**，按"留在近期区"处理 —— 宁可多显示一行，也不把还活着的执行层藏起来
> （运行中的一律算近期）。
>
> **顺序是自己排的，别指望上游**：子会话目录的契约顺序是 **`createdAt` 升序**
> （最老的在最前 —— `dsh-subagent/lib/types/list-children.js:91`），所以次序为
> **跑着的排最前 → 有时间的按新→旧 → 时间未知的按目录倒序**。
> 少了最后一条，时间戳一拿不到界面就**悄悄退回升序**（最新沉底）—— 那种"静默失效"有 5 条
> 断言 + 负对照守着。回归里还有：折叠时 3 天前的旧会话**确实不在**近期区、
> 分组行写的是 `24 小时以外（1 个）`、展开后又能看见它、跑着的永远在最上面。

装的是 `插件\dsh-executor-view\`（**持久客户端插件**，host 半 + `dsh.client` 浏览器半），
用 `插件\install-executor-view.mjs` 挂进 profile 补丁层，**重启 DSH Desktop 后生效**；
卸载是同一个脚本加 `--uninstall`。

正确做法是注册 **`sidebar.right.pane.tab`（键控席位）**，与 DSH 自带的 Files / 引导页并存。
**不要**去占 `rightbar.session` —— 那是 single 插槽，第二个注册者会把整个停靠面顶掉
（slot 目录里写着 `replaceRisk: shadows-shipped-ui`）。

> 曾经设想过走**动态插件**（`cordis_define` / `cordis_run`，需要空会话选 `cordis` preset
> 并在页面上点一次「允许」）。那条路仍然可行，只是动态定义只活在进程内存、重启即失，
> 所以最终选了持久插件。详细对比见 `D:\项目\随便聊聊天\NEXT.md`。
